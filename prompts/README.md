# 本轮 AI 协作记录的阅读方式

原始来源为本次 Codex 会话中的用户可见消息、实际工具调用和输出。保留时间戳与正文哈希；隐去个人本机路径；不导出系统提示、内部推理、密钥或无关作业讨论。JSONL 可机器读取，HTML 可直接阅读。记录是按项目相关性筛选的导出，不能称为账号的完整聊天备份。

本轮真实授权是“改进参赛作品、补齐所有材料、网页演示可靠”。姓名学校和按截图制作均由参赛者明确确认。AI 在这一授权下提出具体实现和验收办法、执行代码修改与测试。下列三个模块链是同一次真实协作的索引，没有人为补造独立的用户提示轮次。

## 链一：资料与问答

需求：把原作品升级为能查证来源的文化资料问答。

实际演进：读取旧数据 → 获取官方名录 → 48 条保留、45 条核验 → 实现 BM25 和原文引用 → 首次运行发现南管漏召回、南音问题混入高甲戏、待核验贝雕召回无关资料 → 增加实体别名表及候选隔离 → 后端回归和 30 条定向问题评测。

证据：`records/本轮真实协作记录.html` 中搜索“南管是什么”“ENTITY_ALIASES”；`evidence/真实修复差异.diff`；`tests/test_core.py` 的 EvidenceTests；`evidence/evaluation.json`。

## 链二：时间约束规划

需求：在半日预算内安排可解释的文化探访策划。

实际演进：检查旧版最短路线宣传与代码 → 明确参考坐标、速度、缓冲、停留和返程边界 → 8 候选、4 站的排列搜索 → 使用总耗时、重复、同城、午夜、不可行预算与交通变化检查实现。

证据：真实调用记录中 `engine.py` 初版补丁；当前 `plan()`；`tests/test_core.py` 的 PlannerTests；`evidence/core-test-output.txt`。这条链的边界设计由 AI 依据用户目标提出，不冒称参赛者曾手写算法 Prompt。

## 链三：保存、恢复与界面可靠性

需求：现场演示完整闭环，保存与导入之后仍可操作。

实际演进：SQLite 与服务端重算 → 浏览器真实操作 → 发现导入自定义时长可能在下拉框丢失 → 恢复时补齐选项 → 再次运行发现同秒保存时记录排序不稳定 → 增加 rowid 作为排序次序 → 检查刷新、改名、删除确认、导出、再导入和 5 种宽度。

证据：实际 `app/main.js`、`server.py` 补丁；`tests/browser_test.py`；`evidence/browser-results.json`。视频中的开发过程页为这些真实记录与代码的回放，不是实时 AI 对话录像。

## 历史材料的边界

`archive/v1/prompts` 来自参赛者原仓库，包含 Prompt 文字、AI 产出摘要和复盘；旧聊天完整导出未提供，因此不能凭这些摘要声称已经验证旧开发全过程。原 12 次 Git 提交完整保留，新增提交按实际开发阶段和当前时间产生。
