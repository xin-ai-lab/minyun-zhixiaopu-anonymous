# 04 · 知识图谱：从第三方图库到自研 SVG

- **日期**：2026-10-28
- **对应模块**：`src/js/modules/graph.js`
- **目标**：可视化展示非遗之间的「类别 / 传承人 / 地域 / 同类」关系网络

---

## Prompt 原文（第一轮）

```
我要在网页里做一个"福建非遗知识图谱"，展示节点（非遗项目、类别、传承人、地市）
之间的关系（分类、传承、地域、同类）。

请推荐技术方案，并给出实现代码。要求能放进纯前端项目，不需要后端。
```

## AI 产出摘要

推荐了 ECharts Graph、D3.js 力导向图、AntV G6 三种方案，并给出了接入示例。

## 选手评审与干预（方案否决）

| 方案 | 体积 | 问题 | 决策 |
| --- | --- | --- | --- |
| ECharts Graph | ~1MB | 体积过大，且需 CDN/打包 | ❌ 否决 |
| D3.js 力导向 | ~270KB | 节点少时布局随机抖动，视觉不稳定 | ❌ 否决 |
| AntV G6 | ~500KB | 依赖重，API 学习成本高 | ❌ 否决 |
| **自研 SVG 环形放射布局** | **0KB** | 需自己写布局算法 | ✅ **采纳** |

**决策理由**：本项目图谱规模固定且不大（≤30 节点），力导向布局的"物理仿真"收益有限，
但引入图库会带来 300KB~1MB 的体积膨胀与额外网络依赖，牺牲「开箱即用、离线可用」的核心优势。

---

## Prompt 原文（第二轮，转向自研）

```
放弃第三方图库。请帮我用纯原生 SVG 手写一个环形放射布局（Radial Layout）：

【输入】
- center：中心节点 { id, label, emoji, color }
- nodes：其余节点数组，每个节点带 ring 字段（'inner' | 'outer'）
- links：边数组 { source, target, label }

【布局规则】
- 中心节点放在画布正中
- inner 环节点均匀分布在内圈（半径 150）
- outer 环节点均匀分布在外圈（半径 215，并偏移一定角度避免与内圈重叠）
- 角度按 i / n * 2π 均分

【渲染顺序】
必须先画线、再画节点，保证节点覆盖在连线之上。

【输出】返回 SVG 字符串
```

## AI 产出摘要

输出了环形坐标计算与 SVG 字符串拼接逻辑，核心约 40 行。

## 选手评审与干预

| 问题 | 修复 |
| --- | --- |
| 节点标签会与圆重叠 | 标签 y 坐标下移至 `p.y + r + 14` |
| 边框线与背景同色不可见 | 节点统一加 `stroke="#fff" stroke-width="3"` |
| 中心相关的连线不突出 | 增加 `.strong` 类：主色虚线加粗 |
| Emoji 不能垂直居中 | 用 `y = p.y + fontSize * 0.32` 近似光学居中 |
| AI 初版的节点分环规则含无效启发式 | 改为基于 `ring` 字段显式分环，逻辑清晰可维护 |

## 最终落地

`renderSVG(center, nodes, links)` 为**纯函数**，输入输出均为可序列化数据，
既可直接用于 DOM，也便于后续扩展（如导出 PNG、单元测试）。
图谱共两种视图：**全局视图**（类别 → 项目，26 节点 / 25 边）与**单项目关系网**。
