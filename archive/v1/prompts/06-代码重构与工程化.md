# 06 · 代码重构与工程化

- **日期**：2026-10-30
- **对应范围**：全仓库（单文件 → 模块化工程）
- **目标**：把原型阶段的单文件 HTML，重构为结构清晰、可维护、可达标的工程仓库

---

## 重构前的痛点

原型阶段为了快速验证，所有代码堆在一个 `index.html` 里（约 900 行）：

- CSS 与 JS 混杂，样式变量散落；
- 全局变量污染（`userImages`、`wikiCache`、`markers` 等十几个全局名）；
- 内联 `onclick="fn('id')"`，函数必须在全局作用域，无法做作用域隔离；
- 魔法数字硬编码（图片宽度 800、车程 30 分钟、检索延迟 1200ms 等）；
- Leaflet 依赖公共 CDN，离线不可用，且 CDN 抖动会直接导致应用不可用。

---

## Prompt 原文

```
请帮我把这个单文件非遗应用重构为规范的前端工程，要求：

【拆分原则】
1. CSS 按职责拆成多个文件（基础层 / 对话区 / 地图区 / 弹窗层）
2. JS 按"数据层 / 能力层 / 编排层"三层拆分：
   - 数据层：纯数据，不含逻辑
   - 能力层：可复用的纯函数或状态机（检索、算法、存储、地图、图谱）
   - 编排层：UI 渲染与交互编排（唯一触碰 DOM 的层）
3. 所有模块挂载到统一命名空间 window.MYX，杜绝全局变量污染

【硬性要求】
- 保持现有功能 100% 不变
- 消除全部内联 onclick，改用事件委托
- 把魔法数字全部抽到 config.js
- 每个文件顶部必须有块级注释，说明职责、算法、AI 协同说明
- 保留并增强原有注释

【额外任务】
把 Leaflet 从 CDN 改为本地 vendor，使项目支持离线运行。
```

## AI 产出摘要

给出了拆分方案的目录树与各模块骨架代码，识别出 `storage / image / rag / planner / map / graph / cross / ui` 八个能力模块。

## 选手评审与干预

| 问题 | 修复 |
| --- | --- |
| AI 建议用 ES Module（`import/export`），但 `file://` 下会被 CORS 拦截 | 改用 **IIFE + 全局命名空间 `window.MYX`**，双击 `index.html` 也能跑 |
| 模块间出现循环依赖（map 调 ui，ui 调 map） | 约定「map 只提供能力，UI 只负责编排」，map 中的弹窗回调用 `MYX.UI.xxx` 延迟绑定 |
| `renderGraphSVG` 里的分环规则含无效启发式 | 改为基于节点的显式 `ring` 字段分环 |
| 数据文件体积大（48 条长文本） | 保留元组存储 + 统一 map 映射的方式，兼顾体积与可读性 |
| 重构后缺少回归验证 | 编写基于 CDP 的端到端自测脚本，覆盖 6 条核心流程 |

## 工程化补充

重构同步补齐了以下工程要件：

- `.editorconfig` —— 统一编辑器风格
- `.eslintrc.json` —— 代码规范检查
- `.gitignore` —— 排除 `node_modules`、`.env`、生成物
- `.env.example` —— 环境变量模板
- `scripts/generate-env.js` —— 零依赖的环境变量注入脚本
- `package.json` —— 脚本化常用命令（`npm start` / `npm run env` / `npm run lint`）
- `CHANGELOG.md` —— 遵循 Keep a Changelog 的版本记录
- `LICENSE` —— MIT 协议
